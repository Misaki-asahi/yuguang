# 余光 · focuspet

> 一个"用余光看着你"的桌面小工具：不录屏、不上传、不评判。
> 白天在你跑偏时轻轻戳一下，晚上给你一张诚实的时间账单。

这是设计方案（`../余光_流程_大纲_设计方案_v1.1.docx`）的**实现版本**，
严格按第三部分第 15.3 节的目录结构落地。

> 应用图标是 `focuspet/assets/icon.ico`（一张网络表情包，仅个人自用）。
> 托盘、控制面板、任务栏、快捷方式都用它；图标文件跟着仓库走，clone 下来就是同一张脸。

**桌宠默认钉在原地**：它不一定自己走——想要它慢悠悠在屏幕上踱步、走累了原地发呆、
碰到屏幕边缘掉头，就把 `config.yaml` 里的 `ui.pet_wander` 改成 `true`
（速度用 `ui.pet_speed`，像素/秒，默认 60）。眼睛会跟着鼠标转；直接拖它也能拖走，
松手后歇两秒再继续。显示层级（始终置顶 / 只在桌面显示 / 不显示）在控制面板里选。

## 快速开始

```powershell
# 1) 先看效果：凭空造一天数据，生成一张示例日报（不碰你的屏幕）
#    用的是独立的 data/demo.db 和 reports/demo.html，绝不会动真实数据
python -m focuspet --demo

# 2) 看一下采集能不能读到你的窗口（只采一次，不常驻）
python -m focuspet --once

# 3) 正式跑（托盘 + 桌宠）
python -m focuspet

# 4) 只要后台、不要界面
python -m focuspet --headless

# 5) 生成并打开某天的日报（同一天重复生成会覆盖，只留一份）
python -m focuspet --report              # 今天
python -m focuspet --report 2026-11-05   # 指定日期
python -m focuspet --report --no-open    # 只要文件，不弹浏览器

# 6) 规则调优：先看哪些窗口没认出来，补完再把历史数据重算一遍
python -m focuspet --unknown 2           # 列出最近 2 天被判为「未识别」的窗口
python -m focuspet --suggest-rules 7     # 模型补过的未知窗口 → 候选规则（只打印不写文件）
python -m focuspet --fill-unknown 2      # 把最近 2 小时仍为「未识别」的窗口重跑一遍（再调一次模型）
python -m focuspet --reclassify          # 用当前规则重跑今天（也可指定日期）
```

依赖（**建议装在项目自己的虚拟环境里**，别装进系统 Python）：

```powershell
cd <仓库根目录>
python -m venv .venv
.venv\Scripts\activate
pip install -r focuspet\requirements.txt
```

不激活也能用，直接调用 venv 里的解释器即可：`.venv\Scripts\python.exe -m focuspet`。

> 为什么要 venv：依赖装在共享 Python 里，那个环境一旦被升级或重置，程序会突然报
> `No module named 'yaml'` 起不来。这套配置就被这么坑过一次，所以自启脚本也优先找 `.venv`。

`PySide6` 只用于托盘和桌宠；缺了会自动退回无界面模式。

**默认节奏**：每 5 秒记一次窗口，**每 10 分钟截一张图**（切换窗口不再补拍）。
想更密就改 `config.yaml` 的 `capture.shot_interval_sec`，或在设置面板里调，不用改代码。

**日报规则**：一天一个文件 `data/reports/YYYY-MM-DD.html`，重复生成直接覆盖（先写临时文件
再原子替换，不会读到写了一半的页面）；生成后**用浏览器打开**——不依赖 `.html` 的系统关联，
因为那玩意儿可能被绑到编辑器上（这台机器就是 VSCode）。浏览器按 Edge → Chrome → Firefox
的顺序找，也可以在 `config.yaml` 的 `report.browser` 里写死路径。

**控制面板**（托盘图标找不到时的主入口）：

```powershell
python -m focuspet --panel      # 启动并打开控制面板；已在运行则唤起
```

面板里能做的事：看今日数字、声明目标（改过之后按钮变成「点击更换目标」，旁边可以选**目标类型**）、打开今日日报 / 本周周报 / 本月月报、
桌宠显示层级（始终置顶 / 只在桌面显示 / 不显示）、暂停采集、开关开机自启、改日报生成时间、退出。

**目标类型**（工作 / 学习 / 休闲 / 生活 / 自动）决定「消耗类算不算跑偏」：目标是
「看完机器学习第 3 讲」时，看视频不该被当成摸鱼——选「学习」它就不会提醒；
不选（自动）就按目标文字猜（「课程 / 网课 / 教程 / 复习 / 作业」→ 学习），
猜不出来按「工作」处理，消耗类仍然会判跑偏（保守）。专注的算法不受影响，
仍然是 `deep_work + 在任务上 + 单段 ≥25 分钟`。

**找不到托盘图标？**

Windows 11 会把新图标默认塞进「隐藏图标」。两条路：

```powershell
python -m focuspet        # 再启动一次：会唤起正在运行的实例，弹出「今日概览」，不会开第二份
```

或者：设置 → 个性化 → 任务栏 → 其他系统托盘图标 → 找到「余光 / pythonw」打开开关。
（`启动余光.bat` 双击也是同样的效果：已经在跑就唤起，没跑就启动。）

**开机自启**（把快捷方式放启动文件夹，不改注册表）：

```powershell
.venv\Scripts\python.exe focuspet\scripts\autostart.py install     # 安装
.venv\Scripts\python.exe focuspet\scripts\autostart.py uninstall   # 卸载
```

快捷方式指向 `.venv\Scripts\pythonw.exe`（无控制台窗口），工作目录是仓库根。
> 某些受限环境（如沙箱）会禁止子进程写启动文件夹，装失败时换一个普通命令行窗口再跑。

**周报与月报**：

| 报表 | 什么时候出 | 文件名 | 手动生成 |
|---|---|---|---|
| 日报 | 每天 22:00 | `reports/2026-11-06.html` | `--report` |
| 周报 | 每周日**跟日报同一时间** | `reports/weekly-2026-W45.html` | `--weekly` |
| 月报 | 每月最后一天**跟日报同一时间** | `reports/monthly-2026-11.html` | `--monthly` |

一周按周一到周日算，月按自然月算。同一周/同一月重复生成只会覆盖同一个文件。
汇总只读 `block` 表（永久保留），所以清掉截图和明细也不影响历史周报。

**周报和月报跟日报同一时间出**（都看 `report.time`），出完会弹一条系统通知：
周日那天是「今日日报 + 本周周报」两条，月末那天是「今日日报 + 本月月报」两条。
想换日子就改 `report.weekly_day`（0=周一 … 6=周日）；想换时间只改 `report.time` 一处。

**数据与缓存**（托盘右键 → 设置 →「数据与缓存」）：

| 项 | 默认 | 说明 |
|---|---|---|
| 截图保留 | 7 天 | 到点自动删 `data/shots/<日期>/` 整个目录 |
| 明细保留 | 30 天 | 删 `sample` 表里更早的行，`block` 与报表永久保留 |
| 自动清理 | 开 | 启动时 + 每天出完日报后各跑一次；删某天截图前会先把那天日报里的图片引用换成说明文字，避免历史报表断图 |
| 查看截图 | — | 打开今天的截图目录（今天还没有就打开截图根目录） |
| 打开工作区目录 | — | 打开含 `focuspet/` 的项目根目录 |
| 立即清理 | — | 按上面的天数立刻清一遍，并告诉你删了多少、释放多少 |

## 怎么接视觉模型

规则能覆盖的那 80% 不花钱，剩下 20% 才交给模型。设置环境变量后填配置：

```powershell
$env:FOCUSPET_KEY = "sk-..."
```

```yaml
# config.yaml
analyze:
  mode: cloud
  endpoint: "https://api.xxx.com/v1"   # 任何 OpenAI 协议地址
  model: "your-vision-model"
  daily_budget_cny: 2.0                # 超了自动降级为纯规则
```

本地模型（Ollama）同理，`endpoint` 填 `http://localhost:11434/v1`。
没有配置时程序照常跑，只是所有段落都由规则产出、置信度偏低。

**模型只补规则认不出的段**，不是整批重算：每个批次先跑规则，挑出 `unknown` 的段，
只把这些段的采样和截图发过去，回来的结论只填进这些时间窗；规则已经认对的段
原样保留。所以规则越准，模型调用越少——高覆盖率的批次几乎不花钱。

模型给出的 `unknown` 结论还会落一张 `vlm_unknown` 表，攒够了可以用
`--suggest-rules` 归纳成候选规则，确认后自己粘进 `config/rules.yaml`。

**补不上会重试**：某一批因为网络抖动或模型答非所问留下 `unknown`，分析线程会在之后
每分钟自动重跑那些窗口（每窗最多 2 次），补到就写回；也可以手动 `--fill-unknown`。
候选规则的 `weight` 固定给 0.7（落在「规则 + 模型交叉验证」那一档），
不会直接当成 0.9 的硬结论——误报比漏报贵。

## 和设计方案的一处差异

设计方案写的是「元数据优先、截图兜底」，实现时发现一个容易踩的坑并已修正：
**Windows 的最大化窗口，`GetWindowRect` 返回的也是整屏矩形**，如果直接拿它判断
「是否全屏」，日常所有最大化的窗口都会被当成全屏，截图就永远不截。
现在先用 `WS_MAXIMIZE` 样式位排除最大化窗口，再比较矩形。

除此之外，代码与文档的对应关系是逐一落实的，主要章节号在文件头的注释里。

## 隐私

- 截图只在本机，按天存 `data/shots/`，默认 7 天清一次。
- 敏感进程（密码管理器等）**连标题都不记**，只留时间戳。
- 标题命中「密码 / 转账 / 工资 / 身份证 / 银行卡」会被替换成 `<sensitive>`。
- 三档模式：`local` / `masked`（默认，裁掉任务栏再发图）/ `meta_only`。
- **「上云」指的是你自己配的 endpoint**：程序不自带任何云端服务。`analyze.endpoint` 空着
  就是全程不联网（当前默认状态）；填了才会把「裁掉任务栏后的截图 + 窗口标题 + 目标」
  发给那个地址。设置面板里会直接显示当前是「不联网」还是「发往某个地址」。
- 如果这台电脑还有别人用，请先给 data 目录加密。

## 已知限制（都是刻意的）

1. **只做 Windows**。手机端是 P2，iOS 基本无解。
2. 只截主屏。多屏用户的副屏活动只有元数据，够用。
3. 判定 ≤ 15 分钟的延迟——提醒依赖批次分析，M2 之前不谈提醒是有原因的。
4. 桌宠是**逐帧动作包**（webp 图集，10 个状态、78–80 帧/个），不是骨骼动画，也没有 Live2D；素材缺失时回退到静态立绘，再缺就回退到 QPainter 手画的小熊。
